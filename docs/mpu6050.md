# MPU6050 / IMU — KP3S Marlin Firmware V1

V1 supports **up to two MPU6050 modules** on the dedicated software-I2C pair:

- SDA -> FFC17 / PD9 by default
- SCL -> FFC16 / PD8 by default
- AD0 LOW -> address `0x68`
- AD0 HIGH -> address `0x69`

`Swap SDA/SCL` exchanges the two logical lines and persists the choice. Two modules may share the same SDA/SCL pair only when their AD0 straps are different.

## Roles

Each legal MPU address has one persistent role:

- `Unused / Não usado`
- `Bed / Mesa`
- `Toolhead / Extrusora`

Both addresses start **unassigned** in V1. A role is unique: assigning Bed or Toolhead to one address removes that same role from the other address. Bed and toolhead keep independent level-zero and temperature-offset calibration data.

Configuration is at `Configuration > MPU6050 / IMU > Devices / Wiring`. Role, wiring and enable changes are locked while a print/job or ordinary planner motion is active.

Selecting a role saves it and immediately returns to the Devices / Wiring menu.

## Menu layout

`Configuration > MPU6050 / IMU` contains:

- `Devices / Wiring`
- `Bed IMU` when assigned and enabled
- `Toolhead IMU` when assigned and enabled
- `Diagnostics`

Each role menu contains:

- `Level`
- `Vibration`
- `Temperature`
- `Calibration`

Calibration contains `Set Level Zero`, `Clear Level Zero` and `Temp Offset`. Clearing the saved level zero requires an explicit Yes/No confirmation. Startup bed-level status is presented automatically on the normal status screen, so it is not duplicated as another role-menu page.

## Detection and bus safety

Only the two legal MPU6050 addresses (`0x68` and `0x69`) are probed. Each detected device is verified by identity/register sanity, configuration readback and a plausible live 14-byte sensor frame. Reads support repeated START and STOP/START fallback.

Full retries, bus recovery, reset/wake and missing-device reprobe are **idle-only**. A bad or disconnected IMU therefore cannot trigger repeated I2C recovery work in the middle of a print.

## Motion isolation

While a print is active or paused, V1 performs no MPU6050 software-I2C transaction. Ordinary homing, jogging and queued planner motion also block background MPU traffic. Polling, detection, recovery and reconfiguration resume only when the printer is motion-idle.

Explicit resonance calibration is separate from background acquisition and only starts when the machine passes its idle/safety gates.

## Resonance assistant

The resonance assistant is at `Configuration > Advanced Settings > Input Shaping > Auto Resonance`.

- X requires the **Toolhead IMU**.
- Y requires the **Bed IMU**.
- Both direct measurements use the same minimum confidence threshold.
- There is no indirect sensor substitution between X and Y.

During a test the required MPU is sampled at a bounded 200 Hz capture rate. The assistant homes, raises Z, disables leveling temporarily, performs the bounded test motion, analyzes the response and restores the prior state before deciding whether to apply a result. A failed or low-confidence test never replaces the current Input Shaping frequency.

## Startup level and temperature

Startup level status represents only the Bed-assigned MPU. Forty quiet samples form the startup estimate. Calibration waits for stable motion before saving a settled zero reference.

MPU temperature is the sensor die temperature, not ambient temperature. Each role has its own persistent `Temp Offset` from -30.0 to +30.0 °C and its own startup temperature baseline.
